# Разметка рамок: bbox → review → golden set

Код этапа разметки в Яндекс Заданиях: два проекта (bbox и review), экзамены и навыки, автоматическая передача ответов между этапами и сборка golden set по 400 фото датасета (`../dataset/metadata.csv`).

## Схема

```
эталон команды (87 доп. CC0-фото, не из датасета; 2 разметчика)
   │ build_gold.py
   ├─► экзамен bbox (10 фото) ──score-exam: F1@IoU0.6 по эталону──► навык bbox_exam ≥ 85
   ├─► обучение + экзамен review (контрольные с известным вердиктом) ──► навык rev_exam ≥ 80
   └─► контрольные задания для пула review, примеры для инструкций

400 фото ─► пул bbox (1 фото/стр., отложенная приёмка) ─sync─► пул review (перекрытие 3)
               ▲                                                │ decide
               │ отклонено в 1-й попытке → новое задание        ▼
               └──────────────────────────── ≥2/3 «OK» → принять (оплачено)
                                             ≤1/3 «OK» → отклонить (не оплачено)
                         2-я неудача / «не уверен» / битая картинка → ручной разбор
принятые + ручной разбор + выборочная проверка ─finalize.py─► golden/golden.jsonl
```

**Кто отвечает за финальную разметку.** Принятый ревью ответ исполнителя. Фото, на которых краудсорсинг не справился, и случайную выборку принятых проверяет команда — её решение финальное, каждое исправление записано с пояснением в `corrections.tsv`.

**Автор не проверяет свою работу.** Роли разделены навыками: в bbox пускаем только без `rev_exam`, в review — только без `bbox_exam`, на каждый экзамен — только без обоих навыков. Дополнительно `decide` отбрасывает вердикт, если ревьюер совпал с автором (в симуляции — 0 случаев).

## Проекты

**bbox.** Вход: `photo_id`, `image` (ссылка `large` из S3 iNaturalist, ≤1024 px; координаты нормированные, от размера не зависят). Выход: `boxes` (json, рамки `{shape, left, top, width, height}` в долях кадра — это и есть формат Контеста), `status` (`butterflies` / `none` / `load_error` — отдельные ответы для «нет бабочек» и «не загрузилась»), `doubt` (галочка «есть объект, в котором не уверен»). Валидация: «выделил» — хотя бы одна рамка; «нет»/«не загрузилась» — ни одной.

**review.** Вход: фото, рамки разметчика (показываются поверх фото, редактирование выключено: `data.internal` + `disabled`, как в примере из документации), ответ разметчика, скрытый `assignment_id`. Выход: `verdict` OK/BAD + тип ошибки (пропуск / лишняя / неточная), из которого собирается комментарий к отклонению.

## Параметры и почему такие

| Параметр | Значение | Почему |
|---|---|---|
| Экзамен bbox | 10 фото, 1 стр., 1,5 ₽, до 40 человек | 6 с бабочками (сначала сложные: несколько, перекрытие, мелкие, обрезанные) + 4 без (сначала похожие насекомые). Встроенная проверка контрольных для рамок не работает (нужно точное совпадение) — поэтому навык ставит скрипт |
| Навык bbox | 100·F1 при IoU ≥ 0,6, порог **85** | 0,6 строже метрики 0,5 — рамки должны быть плотными. В симуляции порог 80 пропускал тех, кто теряет каждую 5-ю бабочку; при 85 таких почти нет. Порог уточняем по распределению на пилоте (`work/exam_scores.tsv`) |
| Пул bbox | 1 фото на страницу, 0,4 ₽, перекрытие 1, отложенная приёмка 7 дней | Приёмка/отклонение каждого фото отдельно — не теряем хорошую работу из-за одной ошибки на странице. Перекрытие 1 + ревью дешевле, чем 3 разметки и агрегация рамок. ~25 с на фото → ~55 ₽/ч |
| Обучение review | ~20 заданий с подсказками, порог 70 | бесплатно, учит правилам на примерах всех типов ошибок |
| Экзамен review | 16 контрольных, 1 стр., 0,5 ₽, до 40 человек, навык = % верных, порог **80** | вердикт категориальный — платформа сама ставит навык (`SET_SKILL_FROM_OUTPUT_FIELD`), как в ДЗ2 |
| Пул review | 9 проверок + 1 контрольная на страницу, 0,6 ₽, перекрытие **3** | 3 голоса — нечётно, ничьих нет; ~1 мин на страницу → ~36 ₽/ч |
| Правило решения | ≥2/3 OK — принять; иначе отклонить и переразметить; 2-я неудача → команда | одна переразметка ограничивает траты; всё, что не сошлось за 2 попытки, — неоднозначно и требует разбора |
| Контроль качества bbox | бан за фото быстрее 4 с (3 из 10); бан при > 35% отклонённых (от 5 ответов) | правило «результаты отложенной приёмки» |
| Контроль качества review | бан при < 70% верных контрольных (от 3); бан за страницу быстрее 15 с (2 из 5) | 70%, а не 60% как в ДЗ2: ответ бинарный, 50% даёт случайное угадывание |
| «Не загрузилась» | скрипт сам проверяет ссылку: открывается → отклонить и переразметить (попытка не считается); не открывается → в ручной разбор | ошибка загрузки ≠ отсутствие бабочки |

## Бюджет (план, комиссия 40%)

| Этап | Расчёт | ₽ |
|---|---|---:|
| Экзамен bbox | 40 × 1,5 × 1,4 | 84 |
| Обучение + экзамен review | 0 + 40 × 0,5 × 1,4 | 28 |
| Разметка bbox | ≤ 400 принятых × 0,4 × 1,4 (отклонённые не оплачиваются) | ≤ 224 |
| Ревью | ~460 ответов × 3 / 9 на стр. ≈ 153 стр. × 0,6 × 1,4 | ~129 |
| **Итого** |  | **~465 из 850** |

Остаток (~385 ₽) — резерв на повторный набор на экзамены и подъём цен. Теоретический максимум (все фото переразмечены, всё принято автоматически, треть страниц ревью неполные) — 896 ₽, поэтому в `cycle` предохранитель: от 700 ₽ переразметки отключаются (отклонённое — на ручной разбор), выше 780 ₽ пулы bbox и ревью закрываются. Смета: `python api.py budget`, фактические траты: `python api.py cost`. Неполная страница ревью выдаётся только через 30 мин, чтобы не платить за страницу из 1–2 проверок.

## Запуск

```bash
pip install requests pillow
python prep.py photos && python prep.py candidates && python prep.py tool
# эталон: двое размечают ОДНИ И ТЕ ЖЕ фото в gold_tool.html → work/gold_<имя>.json
python build_gold.py           # см. work/gold_conflicts.tsv; instruction_img/ → в репо
echo <токен> > ~/.yt_token && chmod 600 ~/.yt_token   # или export YT_TOKEN=...
python api.py balance && python api.py skills && python api.py projects
# в интерфейсе: предпросмотр обоих проектов (несколько бабочек, «нет», «не загрузилась»)
python api.py bbox-exam && python api.py open <exam_pool>   # без --yes только смета; запуск: --yes
python api.py score-exam --loop 10          # отдельный терминал: навыки раз в 10 мин
python api.py rev-exam
python api.py open-training <training> --yes && python api.py open <rev_exam_pool> --yes
python api.py rev-pool && python api.py bbox-pool pilot   # + open обоих
python api.py cycle --loop 5                # отдельный терминал: sync → decide
# пилот: смотрим отклонения и комментарии, правим инструкцию; затем
python api.py bbox-pool main && python api.py open <pool> --yes
python finalize.py queue                    # fix_tool.html → work/fix_<имя>.json
python finalize.py build                    # → ../golden/
python api.py cost
```

Без `YT_TOKEN` все команды `api.py` работают в dry-run: печатают запросы и ничего не меняют.

## Что сохраняется (для отчёта и репозитория)

- `golden/golden.jsonl` — итоговая разметка 400 фото в формате Контеста.
- `golden/golden_meta.tsv` — для каждого фото: группа, источник (`crowd_accept`, `crowd_accept_majority`, `team_fix`, `team_confirmed`; `_model`, если исправляли моделью), число попыток, голоса ревьюеров по раундам.
- `golden/raw_bbox_answers.jsonl`, `golden/raw_reviews.jsonl` — все исходные ответы исполнителей и вердикты ревьюеров.
- `golden/corrections.tsv` — журнал исправлений команды с пояснениями; `golden/pipeline_log.json` — переразметки и причины ручного разбора.
- `work/exam_scores.tsv` — результаты экзамена bbox; `work/state.json` — id проектов и пулов; `work/cost.json` — расходы.

## Проверка без платформы

`python tests/test_pipeline.py` — фейковый API и симулированные исполнители разного качества (рамки случайные, это не разметка). Проверяет: экзамен отсеивает слабых; роли не пересекаются, даже если человек сдал оба экзамена; статусы на платформе совпадают с решениями; не больше одной переразметки; golden — 400 уникальных `photo_id`, координаты в [0, 1].
